# Dev Plan: [IDEA-106] Valkyrie-1 Dynamic State Header — Reader-Progress-Driven Harmonic State Image on Ship Wiki Page
**Theme:** genmedia

## What This Does

The `/artifacts/valkyrie-1` wiki page displays a full-width header image showing one of Valkyrie-1's five canonical harmonic states — selected based on which state appears in the chapters the reader has most recently accessed, derived from `chapter_tags.json`. As readers progress through the story, the ship's wiki page visually "evolves." Zero reader generation cost — uses five pre-approved harmonic state renders already stored in `cel_visual_assets` (after FIX-048 executes).

## Theme-Specific Requirements (genmedia)

1. **Model/provider:** Imagen 4 — images already generated by the author. Zero reader-triggered generation.
2. **Cost per generation:** $0 for readers — all 5 state renders are pre-approved author assets. Author batch cost was ~$0.30 ($0.06 × 5) at generation time.
3. **Caching:** Images stored in Supabase Storage with public URLs, returned by `/api/visuals/preferred?target=valkyrie-1&style={stateSlug}`. The preferred endpoint already exists and returns `{ assetUrl }`. Client component caches the result in React state for the session.
4. **Spoiler gating of prompt inputs:** N/A — no reader-triggered generation. The state slug is world-building vocabulary (dormant/wake/active/alignment/harmonic_jump). Showing "harmonic_jump" imagery to a reader who hasn't reached that chapter in the story reveals only a visual aesthetic, not a narrative event. No spoiler risk.
5. **Canon grounding:** `content/wiki/specs/valkyrie-1/states/{stateSlug}.json` specs were used to generate the original renders. The `ChapterToHarmonicState` mapping is derived from `chapter_tags.json` entity slug lists per chapter and the author's knowledge of which chapters feature each state.

### Phase 2: Custom Artifact Page Override for Valkyrie-1

The generic `/artifacts/[slug]/page.tsx` uses `FictionEntityDetailPage` from `FictionEntityViews.tsx`. In Next.js App Router, a static route (`/artifacts/valkyrie-1/page.tsx`) takes precedence over a dynamic route (`/artifacts/[slug]/page.tsx`). This override intercepts only the Valkyrie-1 artifact page.

3. Create `src/app/artifacts/valkyrie-1/page.tsx`:

```tsx
import { Suspense } from "react";
import { getReaderProgress } from "@/lib/reader-progress";
import { getHarmonicStateForChapter } from "@/lib/wiki/harmonic-state-map";
import { FictionEntityDetailPage } from "@/components/wiki/FictionEntityViews";
import { getWikiEntity } from "@/lib/wiki/entity-loader";
import Image from "next/image";

export default async function Valkyrie1Page() {
  const [readerProgress, entity] = await Promise.all([
    getReaderProgress(),
    getWikiEntity("valkyrie-1", "artifacts"),
  ]);

  const stateSlug = getHarmonicStateForChapter(
    readerProgress?.currentChapterNumber ?? 1
  );

  // Fetch the preferred approved visual asset for this harmonic state
  let headerImageUrl: string | null = null;
  try {
    const res = await fetch(
      `${process.env.NEXT_PUBLIC_BASE_URL}/api/visuals/preferred?target=valkyrie-1&style=${stateSlug}`,
      { next: { revalidate: 3600 } }
    );
    if (res.ok) {
      const data = await res.json();
      headerImageUrl = data.assetUrl ?? null;
    }
  } catch {
    // Fail silently — header image is decorative; page renders without it
  }

  if (!entity) {
    return <div className="p-8 text-center text-[var(--color-ink-muted)]">Not found.</div>;
  }

  return (
    <div>
      {headerImageUrl && (
        <div className="relative w-full h-48 overflow-hidden mb-0">
          <Image
            src={headerImageUrl}
            alt={`Valkyrie-1 in ${stateSlug} state`}
            fill
            className="object-cover object-center"
            priority
          />
          <div className="absolute inset-0 bg-gradient-to-b from-transparent to-[var(--color-bg)]" />
          <div className="absolute bottom-2 right-3 text-xs text-[var(--color-ink-ghost)] uppercase tracking-wider opacity-60">
            {stateSlug.replace("_", " ")} state
          </div>
        </div>
      )}
      <FictionEntityDetailPage entity={entity} readerProgress={readerProgress} />
    </div>
  );
}
```

4. Verify the imports are correct:

5. If `getWikiEntity` doesn't exist with that signature, adapt to use whatever the existing artifacts page uses to load the entity (e.g., `getArtifactBySlug("valkyrie-1")` or similar).

6. Handle the case where `NEXT_PUBLIC_BASE_URL` is not set in the environment — use a server-relative URL instead if needed, or call the `/api/visuals/preferred` handler logic directly (import the handler function from the route module).
