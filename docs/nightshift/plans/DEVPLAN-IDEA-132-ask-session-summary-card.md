# Dev Plan: [IDEA-132] Ask Session Summary Card
**Theme:** ask-forward

## What This Does
After an Ask session reaches 5+ assistant responses and the reader pauses for 5 seconds (idle), a compact "Session Summary" card slides in below the last message. It shows: the number of exchange pairs, the count of distinct wiki entities cited across the session, and a 1-sentence synopsis generated by a single Claude Haiku call ("You explored ALARA's integration with Valkyrie-1 across CH04–CH07"). Gives readers a sense of what they learned without scrolling back. Triggered lazily once per session.

## User Stories
- As a first-time reader with 8 exchanges in a long session: "You explored the Valkyrie harmonic drive and crew dynamics through CH06." → I understand what I covered.
- As a re-reader (show_all_content on): same behavior — summary is generated from the conversation already on screen; no spoiler impact.
- As the author: sessions in the AI ledger gain a natural endpoint signal; the Haiku call is logged in `cel_ai_interactions` like all other AI calls.

## Implementation

### Phase 1: API Route
1. Create `src/app/api/ask/summary/route.ts`:
   ```ts
   import { NextRequest, NextResponse } from 'next/server'
   import Anthropic from '@anthropic-ai/sdk'

   export async function POST(req: NextRequest) {
     const { messages } = await req.json()
     if (!Array.isArray(messages) || messages.length < 4) {
       return NextResponse.json({ summary: null })
     }
     const client = new Anthropic()
     const convo = messages
       .filter((m: { role: string; content: string }) => m.role !== 'summary')
       .slice(-12) // cap at last 12 messages to keep Haiku prompt short
       .map((m: { role: string; content: string }) => `${m.role === 'user' ? 'Q' : 'A'}: ${m.content}`)
       .join('\n')
     const res = await client.messages.create({
       model: 'claude-haiku-4-5-20251001',
       max_tokens: 80,
       system: 'You are a library cataloguer. In exactly one sentence starting with "You explored", summarize the topics covered in this archive conversation. Be specific about entities and chapters mentioned.',
       messages: [{ role: 'user', content: convo }],
     })
     const summary = res.content[0].type === 'text' ? res.content[0].text.trim() : null
     return NextResponse.json({ summary })
   }
   ```
2. **Checkpoint:** `curl -X POST /api/ask/summary -d '{"messages":[{"role":"user","content":"Who is ALARA?"},{"role":"assistant","content":"ALARA is..."}]}'` returns `{ summary: "You explored..." }`.

### Phase 2: Client Integration in `ask/page.tsx`
3. Add refs near the top of the component (alongside existing refs):
   ```ts
   const idleTimerRef = useRef<ReturnType<typeof setTimeout> | null>(null)
   const summaryFiredRef = useRef(false)
   ```
4. Add a `useEffect` that watches `messages` length and restarts the idle timer after each new assistant message:
   ```ts
   useEffect(() => {
     const assistantCount = messages.filter(m => m.role === 'assistant').length
     if (assistantCount < 5 || summaryFiredRef.current) return
     if (idleTimerRef.current) clearTimeout(idleTimerRef.current)
     idleTimerRef.current = setTimeout(async () => {
       summaryFiredRef.current = true
       const entityCount = new Set(
         messages
           .flatMap(m => m.evidence?.linksInAnswer ?? [])
           .map(l => l.href)
           .filter(h => h.startsWith('/characters/') || h.startsWith('/factions/') || h.startsWith('/locations/'))
       ).size
       const res = await fetch('/api/ask/summary', {
         method: 'POST',
         headers: { 'Content-Type': 'application/json' },
         body: JSON.stringify({
           messages: messages.map(m => ({ role: m.role, content: m.content })),
         }),
       })
       const { summary } = await res.json()
       if (summary) {
         setMessages(prev => [
           ...prev,
           { id: 'session-summary', role: 'summary' as const, content: summary, entityCount },
         ])
       }
     }, 5000)
     return () => { if (idleTimerRef.current) clearTimeout(idleTimerRef.current) }
   }, [messages])
   ```
5. Extend the `Message` type (or local interface in `ask/page.tsx`) to include `role: 'summary'` + `entityCount?: number`.
6. In the message render loop, add a branch for `msg.role === 'summary'`:
   ```tsx
   {msg.role === 'summary' && (
     <div className="mx-auto max-w-2xl mt-4 mb-2 px-4 py-3 rounded-md border border-[var(--color-border)] bg-[var(--color-sci-panel)] text-xs text-[var(--color-ink-ghost)] font-mono">
       <span className="block tracking-widest uppercase opacity-60 mb-1">Session Summary</span>
       <p className="text-sm text-[var(--color-ink-muted)]">{msg.content}</p>
       {msg.entityCount && msg.entityCount > 0 && (
         <span className="block mt-1 opacity-50">{msg.entityCount} entity reference{msg.entityCount !== 1 ? 's' : ''} cited</span>
       )}
     </div>
   )}
   ```
7. **Checkpoint:** Start an Ask session with 5+ Q&A exchanges, pause for 5 seconds → summary card appears below the last message. Confirm it fires only once per session (summaryFiredRef prevents re-fire).

### Phase 3: Rate Limit & Error Handling
8. In `src/app/api/ask/summary/route.ts`, wrap the Anthropic call in a try/catch — on error, return `{ summary: null }`. Client already handles `null` gracefully (no card rendered).
9. The `/api/ask/summary` route does NOT require auth (it only processes the messages array passed in the body — no user data, no DB reads). Optional: add a simple body size check (`if (JSON.stringify(messages).length > 20000) return 400`) to prevent abuse.
10. Run `npm run lint` and `npm run build`.

## Content Considerations
No wiki content changes. No new markdown files. The summary is generated from the conversation content already displayed to the reader — no new canon assertions.

## Spoiler & Gating Impact
No spoiler risk: the Haiku summary describes topics from the conversation text already shown to the reader. No new wiki content is fetched; no chapter gating is applied. The summary card appears for all users equally (guests, authenticated, re-readers). No impact on the Ask retriever or spoiler filter.

## Theme-Specific Requirements (ask-forward)
- **Prompt changes:** New `claude-haiku-4-5-20251001` call in `/api/ask/summary`. System prompt is descriptive, not wiki-grounded — the conversation itself is the sole input.
- **Latency budget:** 5s idle + ~0.5–1s Haiku latency = user sees summary ~5.5–6s after their last exchange. Acceptable since the reader is already reading/paused.
- **Conversation-memory storage model:** No new storage. Summary is a client-side transient message added to React state; it is NOT persisted to `cel_conversations` or `cel_messages`.
- **Voice/TTS:** N/A.
